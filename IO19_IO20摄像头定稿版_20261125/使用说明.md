## 复用的 5 个必要条件（缺一不可）

1. **Tools → USB CDC On Boot = Disabled**
   S3 只有一个 USB PHY，IO19/IO20 给了 USB Host 就不能给 USB-CDC。
   烧录需按住 BOOT 再点 RST，或拔掉摄像头上电烧。
   日志走 UART0（TX=43 / RX=44，115200），USB 口只用于烧录。

2. **PSRAM = OPI PSRAM，Flash Size = 16MB**

3. **`lv_conf.h` 中 `CONFIG_LV_DRAW_LAYER_SIMPLE_BUF_SIZE = 24576`，绝不能改成 4096**
   本机 `sdkconfig` 中 `SPIRAM_MALLOC_ALWAYSINTERNAL=4096`：
   malloc ≤4096 字节走内部 RAM，>4096 才走 PSRAM。
   改成 4096 后每块 3840 字节反而落进仅 33KB 的内部 RAM，直接导致语音 TLS 分配失败。

4. **把 `lv_mem_core_clib.c_PSRAM修复版` 覆盖到**
   `%USERPROFILE%\Documents\Arduino\libraries\lvgl\src\stdlib\clib\lv_mem_core_clib.c`
   否则 LVGL 的 <4KB 小对象全挤内部 RAM，出现 `esp-aes: Failed to allocate memory` 并掉线。

5. **内部 RAM 预算**：开机 89KB → 启动后 33KB → UVC 常驻约 15KB → 语音 TLS 需 20KB+
   这是结构性紧张。新增缓冲一律用 `heap_caps_malloc(size, MALLOC_CAP_SPIRAM)`，不要再塞内部 RAM。

## 关键设计决策（不要轻易改）

- **顺序**：抓帧 → 上传识别 → 语音重连 → 解码上屏。
  若先上屏，LVGL 绘制缓冲会把内部 RAM 吃到只剩 1460 字节，`http.POST` 返回 -3。
- **不自动重启**：语音重连失败时只报告，不 `esp_restart()`。自动重启在现场会形成无限循环。
- **上传优先不挂断语音**：挂断虽能腾出 20KB，但上传结束时还不起这笔“债”，重连必失败。
  现只有 https 场景保留挂断重试；服务器实际下发的是明文 `http://api.xiaozhi.me/vision/explain`。
- **抓帧超时 1.5s、连接 5s、读写 12s**：原值 3s/8s/30s 叠加后会让 loop 停摆 90 秒以上。
